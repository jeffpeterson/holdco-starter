business: spinning up new ventures, shared infrastructure, portfolio reviews, capital
allocation, killing/doubling-down decisions, and improving the operating machine itself.

Per-business work lives in **that venture's own** `tasks/` backlog, not here. This file is
for the holding company. See `ventures/` (indexed by `PORTFOLIO.md`) for the businesses
themselves, and `docs/PLAYBOOK.md` for the repeatable flow.

## How to use this file

- **One file per task.** Each task is a markdown file with YAML frontmatter under `tasks/` —
  the source of truth and one merge unit, so parallel agents creating/finishing different
  tasks never race on a push. This `TASKS.md` is a generated index; **don't hand-edit it.**
- **Pick up work** top-down: P0 first, then P1, then P2.
- **Add a task**: `bin/holdco task` opens your `$EDITOR` (git-commit style — first line is the
  title, the rest is the body); it lands **untriaged** in "🆕 Needs triage" below. Scripts/
  agents can pass a title directly: `bin/holdco task "Title"`. Triage with
  `bin/holdco triage <id> P1 Eng`.
- **Claim before you start**: `bin/holdco claim <id>` (sets `status: wip`). Finish with
  `bin/holdco done <id>`.
- **Regenerate** after editing any task: `bin/holdco index`.
- **Blocked on the user?** Set `blocked_on: user` in the task — it rolls up into
  `## Blocked on the user` below.

Status: `[ ]` open · `[~]` wip · `[x]` done · `[!]` blocked
Priority: `P0` urgent · `P1` important, soon · `P2` nice-to-have / later
